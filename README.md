# 会员空间平台 · 闭环一：历史会员批量导入与核对报告的端到端用例

本包为「历史会员批量导入与核对报告」交付物：确定性数据工厂（100 家企业、260 名联系人，故意构造 5 行信用代码错误、3 行重复企业、6 行联系人缺手机号）、Excel 样例（企业 / 联系人两个 sheet）、导入引擎（字段映射预览 → 提交 → 任务状态机）、轮询客户端（最多 60 次、间隔 2 秒、超时给明确失败信息）、独立完整度计算脚本（与引擎不共享实现的第二条路径）、错误报告（8 行逐行给出行号与原因）、抽样比对（10 家 × 6 字段）。

## 一条命令复跑

```
python tools/gen.py             # 重新生成 docs/ 下全部交付物
python tools/verify.py          # 逐条断言 AC（32 条），任何一条失败即非零退出
python -m pytest tests -q       # 用例逐条比对 CSV 期望值
python tools/mutate.py          # 变异测试：改坏引擎 7 处，每处都必须让 verify 变红
python tools/build_docs.py      # 由实跑结果重生成 README / DATA_PROVENANCE / ACCEPTANCE
python tools/make_zip.py        # 打包 + SHA256SUMS
```

## 口径说明

- 数据规模固定：100 家企业、260 名联系人（前 60 家各 3 人、后 40 家各 2 人）。
- 故意构造：5 行信用代码错误（少 1 位）、3 行重复企业（信用代码与前序行相同）、6 行联系人缺手机号。
- 导入成功判定：信用代码必须为 18 位合法字符（不含易混字符）且首次出现；否则该行计入错误报告。
- 错误报告一行一条原因，行号为 Excel 实际行号（第 1 行为表头），格式「第 N 行 | 信用代码 | 原因」。
- 缺手机号不算导入错误：该联系人照常导入，只在完整度上扣分。
- 完整度口径：记录单位为企业（92 家）；6 项 = 企业名称/信用代码/产业方向/会籍档位（企业表）+ 联系人姓名/联系人手机号（取该企业主联系人，即联系人表里该信用代码的第一条）。
- 完整度由两条独立路径计算：导入引擎自算一份，pkg/independent.py 直接读 xlsx 自算一份，两者之差必须为 0。
- 轮询：最多 60 次、间隔 2 秒；超过仍为 running 则抛 ImportTimeout，消息写明次数、间隔、合计秒数与最后状态。
- 抽样：在导入成功的 92 家中按固定步长（每 9 家取 1 家）取 10 家，与源文件逐字段比对 6 个字段。
- xlsx 不比字节（zip 含本地时间与平台标识），跨平台比对对象是单元格值转储 CSV。
